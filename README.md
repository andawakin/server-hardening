# Сервер с нуля: базовая «боевая» настройка Linux-сервера

> Главный проект: чистая Ubuntu Server доводится до состояния, пригодного для продакшена — создание непривилегированного пользователя, вход только по SSH-ключу, отключение входа по паролю и под root, файрвол с открытыми только нужными портами, fail2ban и веб-сервер поверх.

## Описание проекта

Это базовый чек-лист (и автоматизирующий его скрипт) той настройки, которую необходимо выполнить на **любом** новом Linux-сервере перед тем, как размещать на нём реальные сервисы. Проект объединяет шаги из других моих репозиториев (веб-сервер, мониторинг, бэкапы) в единый сценарий первоначальной защиты сервера.

## Стек

- Ubuntu Server 22.04 LTS
- OpenSSH
- ufw (файрвол)
- fail2ban
- nginx
- sudo

## Структура репозитория

```
server-hardening-from-scratch/
├── README.md
├── scripts/
│   ├── 01-create-user.sh         # создание пользователя и выдача sudo
│   ├── 02-ssh-hardening.sh       # настройка входа по ключу и запрет пароля/root
│   ├── 03-firewall.sh            # настройка ufw
│   ├── 04-fail2ban.sh            # установка и базовая настройка fail2ban
│   ├── 05-webserver.sh           # установка nginx
│   └── run-all.sh                # запуск всех шагов по порядку
└── configs/
    ├── sshd_config.diff          # пример изменений sshd_config
    └── jail.local                # конфигурация fail2ban
```

## Порядок действий

### Шаг 1. Создание пользователя и настройка sudo

```bash
sudo bash scripts/01-create-user.sh deploy
```

Скрипт создаёт пользователя `deploy`, добавляет его в группу `sudo`, создаёт директорию `~/.ssh` с нужными правами (700/600).

### Шаг 2. Настройка SSH: вход по ключу, запрет пароля и root

> **Важно**: выполняйте этот шаг только после того, как убедились, что можете зайти под новым пользователем по SSH-ключу в отдельной сессии — иначе рискуете потерять доступ к серверу.

```bash
# На своей машине: скопировать публичный ключ на сервер
ssh-copy-id deploy@<IP-сервера>

# Проверить вход по ключу в НОВОМ терминале, не закрывая текущую сессию root
ssh deploy@<IP-сервера>

# Только после успешной проверки — применить хардненинг SSH на сервере
sudo bash scripts/02-ssh-hardening.sh
```

Скрипт вносит в `/etc/ssh/sshd_config`:
- `PasswordAuthentication no`
- `PermitRootLogin no`
- `PubkeyAuthentication yes`

и перезапускает `sshd`.

### Шаг 3. Файрвол (ufw) — открываем только нужные порты

```bash
sudo bash scripts/03-firewall.sh
```

По умолчанию открывает: `22/tcp` (SSH), `80/tcp` (HTTP), `443/tcp` (HTTPS). Всё остальное — запрещено по умолчанию (`default deny incoming`).

### Шаг 4. fail2ban — защита от перебора паролей/брутфорса SSH

```bash
sudo bash scripts/04-fail2ban.sh
```

Устанавливает fail2ban, включает `jail` для SSH (бан после 5 неудачных попыток на 10 минут, см. `configs/jail.local`).

### Шаг 5. Веб-сервер

```bash
sudo bash scripts/05-webserver.sh
```

Устанавливает и запускает nginx с автозапуском (детали — в отдельном репозитории [`nginx-static-server`](../02-nginx-static-server)).

### Запуск всех шагов разом

```bash
sudo bash scripts/run-all.sh
```

(Шаг с SSH вынесен в интерактивное подтверждение внутри `run-all.sh`, чтобы не потерять доступ к серверу по невнимательности.)

## Проверка результата

```bash
# Пользователь и sudo
id deploy

# SSH — пароль и root отключены
sudo sshd -T | grep -E "passwordauthentication|permitrootlogin"

# Файрвол
sudo ufw status verbose

# fail2ban
sudo fail2ban-client status sshd

# nginx
systemctl is-enabled nginx
curl -I http://localhost
```

## Чек-лист безопасности после выполнения

- [ ] Вход под root по SSH невозможен
- [ ] Вход по паролю отключён, работает только ключ
- [ ] Создан отдельный пользователь с sudo вместо работы под root
- [ ] Файрвол включён, открыты только необходимые порты (22/80/443)
- [ ] fail2ban активен и банит за перебор SSH
- [ ] Веб-сервер работает и доступен на 80 порту
